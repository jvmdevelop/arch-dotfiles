**legis-entropy** is an AI-powered legal analysis system designed to detect contradictions, duplications, and outdated norms in legislative documents. Built for the AI inDrive track by team **jdev**.

## architecture

The system consists of four microservices working in concert:

```
┌─────────────┐    ┌─────────────┐    ┌─────────────┐    ┌─────────────┐
│   Frontend  │    │ Java Backend│    │ Rust Service│    │ ML Service  │
│   (React)   │◄──►│ (Spring Boot│◄──►│ (Scraping)  │◄──►│ (Python)    │
│   Port: 80  │    │   Port:8080)│    │  Port:3001  │    │  Port:8000  │
└─────────────┘    └─────────────┘    └─────────────┘    └─────────────┘
                           │                   │                   │
                           └───────────────────┼───────────────────┘
                                               │
                                      ┌─────────────┐
                                      │Elasticsearch│
                                      │  Port:9200  │
                                      └─────────────┘
```

- **Frontend**: React + TypeScript + TailwindCSS with interactive graph visualization
- **Java Backend**: Spring Boot WebFlux API gateway with OAuth2 authentication
- **Rust Service**: High-performance web scraping and data processing engine
- **ML Service**: Python-based NLP with BERT embeddings and LLM analysis
- **Elasticsearch**: Full-text search and document indexing

## features

- parsing and analysis of regulatory legal documents (NPA)
- detection of contradictions, duplications, and outdated norms
- visualization of relationships between laws using interactive force graphs
- explainability: AI-powered reasoning for why norms are flagged as problematic
- support for Kazakhstan legal databases (Әділет, data.egov.kz)
- export and analysis of open government data
- real-time document similarity search using semantic embeddings
- automated contradiction detection with LLM-powered reasoning
- user authentication via Google OAuth2
- responsive web interface with modern UI components

## quick start

### one-click launch:

```bash
# Clone and start everything (models will be trained if not found)
git clone <repository-url>
cd legis-entropy-
./start.sh

# Or start without training (faster)
./start.sh --skip-train
```

The application will be available at `http://localhost` once all services are ready.

## installation

### prerequisites:

- docker
- docker-compose
- nvidia-container-toolkit (optional, for GPU acceleration)

### environment setup:

```bash
# Copy environment template
cp .env.example .env

# Edit .env with your credentials
# - Google OAuth2 credentials (required)
# - JWT secret (generate with: openssl rand -base64 48)
# - Anthropic API key (optional, for enhanced LLM analysis)
```

### from source:

```bash
docker-compose up --build -d
```

### manual service control:

```bash
# Start all services
./start.sh

# Start without training
./start.sh --skip-train

# Start with LLM fine-tuning (~6 hours, requires GPU)
./start.sh --train-llm

# Reset all models and retrain
./start.sh --reset

# Stop all services
./start.sh --stop

# View training logs
./start.sh --logs

# Check service status
./start.sh --status
```

## development

### local development setup:

Each service can be developed independently:

```bash
# Frontend (React + Vite)
cd frontend
npm install
npm run dev

# Java Backend (Spring Boot)
cd java_backend
./gradlew bootRun

# Rust Service
cd ml
cargo run

# ML Service (Python)
cd ml_service
pip install -r requirements.txt
python app.py
```

### technology stack:

**Frontend:**
- React 19.2.4 with TypeScript
- TailwindCSS 4.2.2 for styling
- Lucide React for icons
- React Force Graph for network visualization
- Vite 8.0.1 for build tooling

**Backend:**
- Spring Boot 3.3.0 with WebFlux (reactive)
- Java 21
- Spring Security with OAuth2
- R2DBC with H2 database
- JWT authentication
- OpenAPI 3.0 documentation

**Rust Service:**
- Tokio async runtime
- Serde for serialization
- Reqwest for HTTP clients
- SQLite for data persistence
- Elasticsearch client

**ML Service:**
- Python 3.11+
- Transformers with BERT models
- PyTorch for neural networks
- FastAPI for REST API
- Sentence Transformers for embeddings
- Qwen2.5-1.5B for LLM analysis

### api endpoints:

- **Frontend**: `http://localhost` - Web interface
- **Java Backend**: `http://localhost:8080` - API gateway with Swagger UI at `/swagger-ui.html`
- **Rust Service**: `http://localhost:3001` - Scraping and graph API
- **ML Service**: `http://localhost:8000` - ML/NLP endpoints
- **Elasticsearch**: `http://localhost:9200` - Search cluster

## configuration

### key environment variables:

```bash
# Authentication
GOOGLE_CLIENT_ID=your_google_client_id
GOOGLE_CLIENT_SECRET=your_google_client_secret
JWT_SECRET=your_32_character_minimum_secret

# ML Models
BERT_MODEL=sentence-transformers/paraphrase-multilingual-mpnet-base-v2
LLM_MODEL=Qwen/Qwen2.5-1.5B-Instruct
LLM_4BIT=true  # Enable 4-bit quantization for reduced memory usage

# Training Control
SKIP_TRAINING=false    # Skip model training on startup
TRAIN_LLM=false        # Enable LLM fine-tuning (requires GPU)
COLLECT_LIMIT=500      # Number of documents to collect for training
```

### gpu acceleration:

For optimal performance with ML models:

```bash
# Install NVIDIA container toolkit
curl -fsSL https://nvidia.github.io/libnvidia-container/gpgkey | sudo gpg --dearmor -o /usr/share/keyrings/nvidia-container-toolkit-keyring.gpg
curl -s -L https://nvidia.github.io/libnvidia-container/stable/deb/nvidia-container-toolkit.list | sed 's#deb https://#deb [signed-by=/usr/share/keyrings/nvidia-container-toolkit-keyring.gpg] https://#g' | sudo tee /etc/apt/sources.list.d/nvidia-container-toolkit.list
sudo apt-get update && sudo apt-get install -y nvidia-container-toolkit
sudo nvidia-ctk runtime configure --runtime=docker
sudo systemctl restart docker
```

## troubleshooting

### common issues:

1. **Services fail to start**: Check Docker logs with `docker-compose logs [service-name]`
2. **ML service takes long to start**: Initial model training can take 10-30 minutes
3. **GPU not detected**: Ensure nvidia-container-toolkit is properly installed
4. **Authentication errors**: Verify Google OAuth2 credentials and redirect URIs

### health checks:

All services include built-in health checks:

```bash
# Check individual service health
curl http://localhost:8080/health  # Java Backend
curl http://localhost:3001/api/graph/status  # Rust Service  
curl http://localhost:8000/health  # ML Service
curl http://localhost:9200/_cluster/health  # Elasticsearch
```
